# Decisions

1. **Python 3.10+.** Only 3.10 is installed locally; nothing in the plan needs 3.11 features. `requires-python = ">=3.10"`.
2. **Library depends on numpy only.** CSV parsing uses the standard `csv` module, so the library stays small and strictly typed. pandas is used only by the Streamlit app (it is a Streamlit dependency anyway).
3. **No real data supplied.** Equipment figures are illustrative placeholders and the metered example is synthetic, both labelled everywhere. A git-ignored `data/equipment.local.csv` overrides the illustrative library.
4. **CI.** The GitHub `workflow` token scope is not granted for the publishing account, so workflow files live in `docs/ci/` until it is.
5. **Commit identity.** Commits use the GitHub no-reply address, never a work machine email.
6. **Calibration defaults to one global scale.** Measured on the synthetic example, per-category fitting from ~11 weeks was poorly conditioned (see VALIDATION.md). Global is the default; per-category is an advanced mode with an explicit warning. The result always carries warnings and an `improved` flag, and the app will not let a proposal that failed the held-out check be applied.
7. **A calibration never overwrites the user's figures.** It is applied as a layer on top, shown in a banner, and removable.
8. **Synthetic example assumption.** The metered sample assumes the illustrative library under-estimates by about 25%. That is a demo scenario, labelled everywhere.
9. **Hosting: GitHub Pages via stlite.** Pages serves static files only, so the Streamlit server cannot run there. Options weighed: (a) the same app in the browser via stlite, (b) the Python library behind a hand-built page on Pyodide, (c) a TypeScript port. Chose (a): smallest change, one code path, the library tests stay meaningful. Cost: a heavy first load (about 41 MB, 13 to 23 s measured), a CDN dependency, and no offline use. The in-browser runtime is Python 3.14 with pandas 3, so the headline numbers were compared with the native run (identical) and the full calibration flow was driven in a real browser, but that browser check is manual, not part of the automated suite.
10. **Pinned CDN version.** stlite is loaded at an exact version (`STLITE_VERSION` in `scripts/build_site.py`, enforced by a test), never "latest".
11. **Two bugs found by looking at the real page**, not by tests: the calibration chart's x axis was titled "start, end, Week" (layered charts merge axis titles; now set explicitly), and a Deploy button showed in the toolbar (now minimal mode).
12. **Styling is plain CSS and HTML inside Streamlit, in one module (`app/style.py`).** No component library, so it runs identically natively and in the browser build. All user-supplied text placed in HTML is escaped (a test covers it). The KPI figures stay real `st.metric` widgets rather than hand-drawn HTML, so they remain accessible and testable; only their appearance is customised. Charts use a navy, amber and orange palette with the peak labelled. The "where the demand comes from" chart reuses the already-tested `category_matrix`, whose layers plus the base load equal the central estimate.
13. **Top tabs instead of a sidebar.** The sidebar mixed setup, uncertainty and sizing controls with the content and felt like a stock Streamlit app. The page now has four tabs (Project, Estimate, Calibrate, Export & notes). Uploads and reset moved into a "Load your own data" panel in the Project tab; the Monte Carlo trials, seed and headroom controls sit at the top of the Estimate tab, next to what they change. Checked in a real browser that re-running the page (for example pressing Apply) keeps you on the same tab. In Streamlit 1.65 the tabs are `div[role="tab"]` elements with `data-testid="stTab"`, not the older BaseWeb buttons, so the tab CSS targets those.
14. **Schedule slip is an opt-in extra in the Monte Carlo, drawn from its own random stream.** Each hire may start 0 to N whole weeks late (uniform); the part pushed past the last week is dropped. It uses a second seeded stream, so switching slip on never changes the load-factor draws, and slip 0 reproduces the old result exactly (tested). Uniform delay is a simple placeholder, not a fitted distribution.
15. **Overview first, editing second.** The first thing a visitor sees is the result (cards and charts), not the input tables; the schedule moved to a Project tab. Trials and seed live on a Detail tab.
16. **A hand-written PDF report.** The PDF is written directly (one or two A4 pages, built-in Helvetica, vector chart) so it runs unchanged in the browser build with no extra dependency. The file structure is checked by a test and it was viewed in a PDF reader. Text is limited to Latin-1.
17. **Visual style: a light grey dot-grid sketchpad.** White cards with large radii, pill buttons, yellow plus three other accents, one soft shadow (the tab bar). Poppins loads from Google Fonts, so with no network the page falls back to a system font. The earlier navy, cream and monochrome versions were tried and dropped.
18. **One warning, as a flashing badge.** The planning-estimate disclaimer and the illustrative-data warning are a single dropdown notice, not banners, to keep the page uncluttered.
